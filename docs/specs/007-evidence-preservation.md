# 근거 보존과 원문 단위 인용

## 사용자 동작
질문에 등장한 모든 범주가 하나의 측정에 없더라도 검색한 원문을 답변에 전달한다. 그래프는 검색의 허가 조건이 아니며, 공통 개념 및 검색된 실험·측정·문단에서 추가 근거를 선택한다. 기존 12편과 정규화 사전은 유지한다.

## 선택 계약
- SDK가 반환한 원문 문단은 원래 검색 순서로 먼저 보존한다. 개념 매핑 실패가 검색 실패가 되어서는 안 된다.
- SDK 개체·관계 및 원문과 연결된 실험/측정도 탐색 시작점이다. 범주 교집합은 순위 신호이며 탈락 조건으로 사용하지 않는다.
- 직접 검색 근거와 연결 강도를 기준으로 순위화하고 문헌 다양성을 유지한다. 질문 문장, 문헌 ID 또는 정답 값에 대한 분기는 금지한다.
- 16,000토큰 범위에서 원문을 먼저 넣고 연결된 실험 정의와 측정의 원문을 추가한다. 기본 검색 원문 자체가 상한을 넘으면 조용히 버리지 않고 명시적인 오류로 처리한다.

## 인용 계약
생성 모델에 전달하는 번호는 실제 원문 문단 하나와 대응한다. 여러 문단에서 추출된 조건을 단일 문단의 인용으로 포장하지 않는다. 실험군과 측정 기록은 사용자 화면과 경로 연결에 사용하며 해당 원문 번호를 참조한다. 답변 생성 프롬프트는 원문 단위로 시료·조건·값을 인용한다. 모델 출력의 번호 존재 검사만으로 의미적 일치를 통과 처리하지 않는다.

## 검증
결정적 회귀 테스트를 먼저 작성한다. 구현 담당자와 분리한 검토자가 기존 15개와 중복되지 않는 새 질문 및 필수 근거를 작성한다. 구현과 질문을 고정한 뒤 12개 질문 × naive/graph 두 방식 = 24회 생성 상한으로 실행한다. 같은 원문, 모델, 프롬프트와 상한을 사용한다. 별도 선택 로직 회귀는 API 호출 없이 확인한다. 기존 평가와 새 질문의 점수를 직접 개선율로 계산하지 않는다. 근거 회수와 답변 완결성, 수치별 원문 일치를 구분하고 불일치를 기록한다. 평가 후 결과를 맞추기 위해 질문·정답을 수정하지 않는다.

## 범위와 종료
논문 확장, 새 추출, 질문별 예외 규칙은 추가하지 않는다. 보고서, 실제 화면, CI와 독립 리뷰를 확인한 뒤 이슈를 종료한다. 새 평가에서 남는 오류를 완전 해결로 표현하지 않는다.
