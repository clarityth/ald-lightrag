# 저장된 12개 질문의 문맥 예산 비교

저장된 H01–H12의 graph 검색 문단 10개를 두 방식의 공통 출발점으로 사용했습니다. graph 방식은 저장된 최종 문맥의 문단 순서를 따릅니다. 문헌 확장 방식은 검색 문단이 속한 논문을 검색 문단의 첫 등장 순서로 나열하고, 각 논문의 나머지 문단을 원문 순서대로 한 문단씩 순환하며 추가합니다. 두 방식 모두 문단 전체를 `_context` 형식으로 만들었을 때 4,000·8,000·12,000토큰 상한에 들어가는 경우에만 추가하고, 초과하는 문단은 건너뛰고 다음 문단을 확인했습니다. 검색 문단에도 같은 규칙을 적용했습니다.

| 문맥 상한 | 방식 | 필수 측정 근거 회수 | 평균 실제 문맥 토큰 |
|---:|---|---:|---:|
| 4,000 | 저장된 graph 순서 | 35/45 (77.8%) | 3,946.6 |
| 4,000 | 문헌 순환 확장 | 30/45 (66.7%) | 3,988.2 |
| 8,000 | 저장된 graph 순서 | 35/45 (77.8%) | 7,727.1 |
| 8,000 | 문헌 순환 확장 | 30/45 (66.7%) | 7,980.5 |
| 12,000 | 저장된 graph 순서 | 38/45 (84.4%) | 10,636.5 |
| 12,000 | 문헌 순환 확장 | 34/45 (75.6%) | 11,979.9 |

필수 근거 회수는 질문 파일에 기록된 측정별 필수 문단이 모두 선택됐는지만 사후 계산했습니다. 정답은 문단 선택이나 순위에 사용하지 않았습니다. 12,000토큰에서 graph는 H07·H08·H11의 근거를 더 회수했고, 문헌 확장은 H06의 근거를 더 회수했습니다. 다른 질문에서는 두 방식의 회수 개수가 같았습니다. 질문별 선택 문단 순서와 실제 토큰, 건너뛴 문단, 필수 측정 ID는 [budget.json](budget.json)에 저장했습니다.

토큰 계산에는 `tiktoken.encoding_for_model('gpt-4o-mini')`와 저장된 구현의 원문 `_context` 형식을 사용했습니다. 12개 graph 전체 문맥의 재계산 토큰 수가 기존 비교 파일의 저장 수치와 각각 일치했습니다. 입력 자료의 SHA-256은 JSON에 기록했습니다.

이 결과는 기존 12개 질문과 저장된 graph 검색 결과를 재사용한 사후 분석입니다. 두 방식의 상한이 같아도 실제 사용 토큰은 다릅니다. 문맥 토큰은 모델 전체 입력 토큰이나 청구 비용이 아니며, 새 답변의 정확도·인용 품질·응답 시간·실제 API 비용을 측정하지 않았습니다. 공통 검색 문단이 graph 실행에서 나온 것이므로, 이 결과만으로 독립 검색 방식 전체의 우열이나 다른 질문에 대한 일반적인 우위를 판단할 수 없습니다.

재생성은 저장소 루트에서 `python3 evaluation/budget_check.py`를 실행하면 됩니다. 이 명령은 로컬 JSON만 읽고 결과 JSON을 다시 작성하며 모델 API를 호출하지 않습니다.
